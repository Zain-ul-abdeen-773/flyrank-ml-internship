CTR Opportunity Scoring for SEO Content Optimization

Zain-ul-Abdeen · Lane 4: CTR / Engagement Opportunity Scoring · August 2026
GitHub Repository

Abstract

How can SEO teams systematically identify pages that underperform their expected click-through rate given their search ranking? We built a Random Forest regression model trained on aggregated Google Search Console and GA4 metrics from a 79-million-row production warehouse, predicting expected CTR as a function of average position, session volume, and content intent. On a grouped validation split (no client leakage), the model achieved a lower MAE than the hardcoded three-bucket baseline, producing a ranked queue of content optimization opportunities. The resulting action playbook provides directional decision-support for editorial teams, not automated deployment, with explicit no-go cases and monitoring triggers documented throughout.

1. Introduction / Problem Statement

Organic search remains the primary traffic channel for content-driven websites. Google Search Console exposes per-page metrics including impressions, clicks, average position, and CTR. However, raw CTR alone is misleading: a page ranking at position 1 with 5% CTR is far more problematic than a page at position 15 with the same CTR, because position 1 commands a much higher expected click share.

The core question driving this work: Which pages have the largest gap between their expected CTR (given their ranking) and their actual CTR, weighted by search volume? This gap, which we call the CTR Opportunity Score, represents the estimated number of missed clicks recoverable through title and meta description optimization.

A simple rule-based baseline (position 1-3 = 20% expected CTR, 4-10 = 5%, 11+ = 1%) was built first. The modeling phase then attempted to improve on this baseline using a Random Forest trained on richer features.

3. Methodology

3.1 Assumptions

  • CTR is primarily a function of average search position, with secondary effects from content intent and user engagement (sessions).
  • The relationship between position and CTR is non-linear (exponential decay), making tree-based models more appropriate than linear regression.
  • Pages within the same client portfolio share structural CTR patterns; validation must account for this to avoid inflated metrics.

3.2 Features

FeatureSourceKnowable at Decision Moment?
avg_posGSC trailing 30dYes
sessionsGA4 trailing 30dYes
content_intentdim_contentYes (structural metadata)

3.3 Label Definition

The target variable is actual_ctr = clicks / impressions * 100, computed from the same trailing 30-day window. This is not a forecast; we are performing anomaly detection within the current snapshot to find pages where actual CTR deviates from the position-based expectation.

3.4 Baseline

A hardcoded step-function maps position buckets to expected CTR:

Position BucketExpected CTR
1 - 320%
4 - 105%
11+1%

The baseline score for each page is (expected_ctr - actual_ctr) * impressions, representing estimated missed clicks.

3.5 Model

RandomForestRegressor(n_estimators=100, max_depth=10) trained on one-hot-encoded features. The Random Forest was chosen for its ability to capture the non-linear CTR decay curve without requiring manual feature engineering.

3.6 Validation Design

Week 5 (Naive): Random 80/20 train-test split. This allows URL-level patterns from the same client to leak across the split boundary.

Week 6 (Honest): GroupShuffleSplit on client_hash_id, ensuring no client appears in both train and test sets. This tests genuine generalization to unseen clients.

3.7 Leakage Checks

Verified safe: No feature in the model contains clicks or impressions directly (which would create a mathematical tautology with the CTR target). The avg_pos and sessions features provide independent signals about page quality and user engagement.

Week 3 trap demonstrated: Adding a magic_engagement_score derived from clicks_30d inflated R-squared to near 1.0, confirming that feature leakage is detectable and was excluded from the final model.

Note: Exact metric values are generated dynamically when the notebook executes against the live warehouse. The directional finding is consistent: the Random Forest achieves lower MAE and higher R-squared than the hardcoded baseline on the grouped split.

4.2 Honest Split Impact

When switching from a random split to the grouped-by-client split, R-squared dropped slightly, confirming that the naive split was inflating performance by memorizing client-specific CTR baselines. The grouped split provides a more honest estimate of how the model would perform on a brand-new client's content.

4.3 Feature Importance

Permutation importance analysis confirmed that avg_pos is the dominant predictor, followed by sessions. Content intent provides marginal additional signal.

5. Limitations and Honest Framing

  • SERP Blindness: The model sees average position, not actual pixel depth on the results page. Google Ads, Shopping Carousels, AI Overviews, and Featured Snippets all compress organic real estate without changing the reported position.
  • Branded vs Non-Branded: All impressions are pooled. A competitor's branded term where we rank #2 will always have low CTR regardless of title quality.
  • Single Month Snapshot: All training and evaluation use month=2026-03. Seasonal effects, algorithm updates, and content freshness changes are not captured.
  • No Causal Claims: This analysis observes correlations between position and CTR. We do not claim that rewriting a title will cause a specific CTR increase. The output is directional decision-support for human review.

6.2 Human Review Rules

  • Every REVIEW_TITLE_AND_META flag requires an editor to inspect the live Google SERP before making changes.
  • The editor must confirm that the current title is objectively less compelling than competing results.

6.3 No-Go Cases

Never automate title deployment. Changing a title tag can drop a top-3 ranking entirely. The risk of losing an established ranking far outweighs a marginal CTR improvement.

  • Pages flagged as ZERO_CLICK_ANOMALY are excluded from review queues.
  • Branded competitor queries are excluded (no amount of title optimization will steal navigational clicks).

6.4 Monitoring and Retrain Triggers

  • Action Completion Rate: If fewer than 10% of flagged pages receive a review, the model is generating too many false positives.
  • Google Core Updates: Major SERP layout changes invalidate the expected CTR baselines. Retrain on post-update data.
  • Feature Drift: If the median CTR of the zero-click bucket changes by more than 2 percentage points, trigger a manual threshold audit.
